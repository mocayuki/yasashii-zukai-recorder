## 1. 目的

自分専用の Mac アプリとして、次を 1 つの場所で行う。

- 話したことをマイクで録音し、ノートを付けて残す
- 自分の画面と自分の声を収録し、ノートと時刻メモを付けて残す（相手の声は対象外）
- 画面収録を見やすく編集（クリック位置へなめらかに寄る自動ズーム、手動ズーム、前後カット）して、YouTube にそのまま上げられる mp4 に書き出す
- 収録から文字起こし・字幕・要約を作る（外部 API 利用可）

録音・録画ファイルはリポジトリには入れず、自分のパソコンの指定フォルダーに保存する。

## 2. 決めたこと

| 項目         | 決定                                                                                                                                               | 理由                                                                                                                                            |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 形態         | デスクトップアプリ（Mac）                                                                                                                          | ボタン 1 つで起動でき、フォルダー保存・空き容量・長時間の順次保存を確実にできる                                                                 |
| 保存先       | ユーザーが指定するフォルダー。初期値は `~/Library/Application Support/やさしい図解レコーダー/library/`（以前は `~/Downloads/やさしい録音ノート/`） | リポジトリの外に置く。バックアップはこのフォルダーを丸ごとコピーすれば済む                                                                      |
| ブラウザー版 | 作らない                                                                                                                                           | ブラウザーから指定フォルダーへ順次保存できるのは Chrome だけで、**Safari と Firefox では使えない**。空き容量も取得できない。iPhone でも使えない |
| ホスティング | しない                                                                                                                                             | 費用がかかるうえ、ローカルのフォルダーへ保存する要件を満たせない                                                                                |
| 費用         | アプリ自体は無料。文字起こしなどの API 利用分だけ従量                                                                                              | 後述の目安を参照                                                                                                                                |
| 作り直し     | 既存コードは作り直す                                                                                                                               | 画面部品は全面的に変わる。録音の仕組み・IndexedDB 層・デザイン CSS は移植する                                                                   |

## 3. 技術構成（提案）

### 3.1 全体

```
Electron（macOS アプリの殻・ファイル保存・空き容量・画面一覧）
  └─ SvelteKit（画面。adapter-static でビルドした静的ファイルを読み込む）
       └─ Web API（MediaRecorder / getDisplayMedia / WebCodecs / Canvas）
ffmpeg（同梱の実行ファイル。mp4 書き出し・字幕焼き込み・音声抽出）
```

- **Electron を選ぶ理由**: 中身が Chrome と同じなので、いま動作確認済みの録音・画面収録の挙動がそのまま使える。ズーム書き出しに使う WebCodecs も揃っている。ネイティブ側（Node）でファイル追記・空き容量・フォルダー選択ができる。
- **Tauri を選ばない理由**: アプリは小さくできるが、Mac の WebView（WKWebView）は画面収録 API の対応が不確かで、収録形式も変わる。確認と回避策に時間を取られる可能性が高い。
- **SvelteKit を選ぶ理由**: 部品（コンポーネント）を小さく分けやすく、状態管理が素直で、コード量が少なく読みやすい。サーバー機能は使わず、静的ビルドだけ使う。
- **ffmpeg を同梱する理由**: mp4（H.264 / AAC）への変換、字幕の焼き込み、音声だけの抽出が確実にできる。

### 3.2 起動方法

- 配布物: `release/mac/YasashiiZukaiRecorder.app`（アプリケーションフォルダーでは `やさしい図解レコーダー.app` にして置く）。.app の中の名前（実行ファイル・補助アプリ・CFBundleName）は英字。日本語名（特に濁点付きの「ダ」）だと Electron が CFBundleName から組み立てる補助アプリのパスと NFD のファイル名が食い違い「Unable to find helper app」で落ちる。見た目の名前は CFBundleDisplayName。`npm run package` で `release/mac/` にでき、アプリケーションフォルダーに入れて Dock から開く（2026-09-11 から、ふだんはこの .app を使う。開発用の `npx electron` は同時に開けない: 同じ保存先を使うため 1 つだけにしている）。アイコンは `scripts/make-icon.mjs` で作る `resources/icon.icns`。署名は ad-hoc（`scripts/adhoc-sign.mjs`。Apple の開発者アカウント無しで付けられる仮の署名）。無署名だと macOS が身元を覚えられず、マイクの許可を起動のたびに聞くため。ad-hoc でも作り直すたびに 1 回は聞き直される（完全に覚えさせるには Developer ID 署名が要る）。
- 開発時: `npm run dev` で Electron と SvelteKit が同時に立ち上がる。
- 自動更新は付けない（個人用）。新しい版はビルドし直して入れ替える。

### 3.3 データの置き場所

```
~/Library/Application Support/やさしい図解レコーダー/library/   ← 設定で変更できる
  library.json                          ← ノート・収録の一覧（メタ情報）
  notes/<noteId>.json                   ← ノート（タイトルとノードの木）
  media/<recordingId>.webm              ← 収録の原本（順次追記）
  media/<recordingId>.json              ← 収録のメタ情報（形式・トラック・長さ）
  exports/<recordingId>-<日時>.mp4      ← 書き出した動画
  transcripts/<recordingId>.json        ← 文字起こし（単語と時刻）
  transcripts/<recordingId>.srt         ← 字幕
```

- 収録中は 1 秒ごとのデータをそのまま `media/*.webm` に追記する。メモリーに全量をためない。途中でアプリが落ちても、追記済みの部分は再生できる。
- ノートは 1 件 1 ファイルの JSON。中身が見え、フォルダーごとコピーすればバックアップになる。
- アプリの設定（保存先、API キー）は Electron の userData に置く。API キーは macOS のキーチェーンに保存し、リポジトリにも保存フォルダーにも入れない。

### 3.4 既存データの移行

- 現在の初期版（ブラウザー、IndexedDB）で保存した録音は、初期版の「バックアップを書き出す」で JSON にし、新アプリの「読み込み」でフォルダーへ取り込む。
- 取り込み後は、初期版のブラウザーデータは消してよい。

## 4. 機能

### フェーズ 1: 土台とノート

- アプリ起動、保存先フォルダーの選択と表示、使用容量と空き容量の表示
- ノートの新規作成・編集・削除。録音がなくても作れる
- 本文はマインドマップ（ノードの木）。左にタイトル、クリックすると子ノードが右に開き、子をさらに開くと孫が出る。ノードごとに文字を書き、子・兄弟の追加、削除、折りたたみ、チェック（☐/☑）ができる
- 見た目: すべてのノードは丸い枠。選択中は黄色地、それ以外は白地の黒枠。線は親の右端の中央から子の左端の中央へ。他ツールの下線スタイルは使わない
- 動き: ホイールで拡大縮小、背景のドラッグで移動（手のカーソル）、どちらもなめらかに補間する。開閉のとき、操作したノードとその先祖は動かさず、兄弟が場所を空ける。ノードはドラッグで自由に動かせ、背景の点の格子に吸い付く
- タイトルと中心ノードは別。タイトルは枠の上・中央に出す（動画の題名）。中心ノードは自分の文字を持ち、ほかのノードと同じ仕組み（開閉ボタン、＋、文字の編集）で扱う
- 同じ木を Markdown として編集できる。`# タイトル`、その次の本文行が中心の文字（省くとタイトルと同じ）、`- ノード`（字下げで子）、`- [ ]` チェック。AI に作らせて貼り付ける前提の決まり
- 注釈（ノードの補足を枠の下部に出す機能）は 2026-09-12 にやめた（テロップに被る、設定しにくい、ごちゃごちゃする）。Markdown の `> 注釈` は昔のノートのために読み書きだけ残し、画面には出さない
- ⌘Z / ⌘⇧Z で元に戻す・やり直す（ノートごとに 100 段階）
- 自動保存。「保存中 / 保存済み hh:mm / 保存に失敗（再試行）」を常に表示
- ノート一覧と検索（タイトル・本文・時刻メモ・文字起こし）
- 初期版バックアップ JSON の取り込み

### フェーズ 2: 収録

- 収録の対象は「ワークスペースの黄色い枠の中」。自分の画面の中身を取り込み（Electron が自分のフレームを渡すので OS の許可は不要）、枠の部分だけを 1920×1080 の canvas に描き写して、マイクの音声と一緒に webm（VP9 / Opus）で録る。ウィンドウの大きさに関係なく同じ画になる
- 1 秒ごとに保存先の `media/<id>.webm` へ追記する（メモリーに全量をためない）。開始時にメタ情報を `status: recording` で書き、終了時に長さ・波形・しるしを書いて `complete` にする。終了処理まで行けなかったものは起動時に `recovered` として一覧に戻す
- 音声の波形は録りながら 1 秒に 20 個の山の高さを計算してメタ情報に入れ、再生画面で波形として出す（クリックで頭出し）
- 収録中にノードを選ぶと、その時刻と文字が「しるし」として残る（あとで編集や AI に渡す材料）
- 収録中は追加・編集のボタンを隠す（開閉と選択はできる）。閉じる・戻す・Markdown 編集は止まる
- マイクの許可は macOS のダイアログに任せる。許可が無いときは日本語で案内する
- 「音の設定」でマイクとスピーカーを選べる。開いている間はマイクの音量メーターが動き、収録前に声が入っているか確かめられる。収録中に 3 秒以上無音なら赤い警告を出す（ミュートや装置違いに気づけるように）
- BGM: 保存先の `bgm/` の音楽ファイルから 1 曲選び、音量を決める。収録には入れず（声だけをきれいに録る）、書き出し（mp4）のときにその音量で重ねる。同時収録では声と BGM が干渉して音が変になったため。「ダウンロードフォルダーの音楽を移動して取り込む」でまとめて移せる
- マイクはエコー除去・雑音除去・自動音量を切って録る（声を押さえたり歪めたりしないため）
- 保存先の既定は `~/Library/Application Support/やさしい図解レコーダー/library/`（アプリ自身の置き場所）。ダウンロードフォルダーは整理で消えやすいため、そこには置かない。以前の既定（`~/Downloads/やさしい録音ノート/`）を使っていたら、起動時に丸ごと移す（同じディスクなら rename で一瞬）。BGM は `~/Library/Application Support/やさしい図解レコーダー/bgm/`（保存先を変えても付いてくる）
- ノードの画像: ノードの操作の「画像を付ける」でファイルを選ぶと保存先の `images/` に写し、ノードの下に出す（最大 300×220）。Markdown では `![画像](images/xxx.png)` の行（ノードの直後）。外しても画像ファイルは消さない（⌘Z で戻せるように）
- ドラッグで木の形も変えられる: ドラッグ中のノードの中心を別のノードの上に重ねると、そのノードが黄色い太枠になり、離すとその子になる。別のノードのすぐ上・下（隙間）に持っていくと黒い横線が出て、離すとその兄弟として前・後ろに入る（手で動かした位置は消えて自動配置に戻る）。どちらでもない所で離せば、ただ位置が動くだけ（従来どおり）
- 一覧（左）の幅は境目のつまみをドラッグして変えられる（220〜600px。この Mac の localStorage に覚える）。ウィンドウの位置と大きさは動かすたびに設定に覚え、次に開くときに戻す（その画面が無ければ既定の大きさ。全画面中は覚えない。ワークスペースは同じウィンドウなので同じ扱い）
- 一覧（左）のノートは題名だけの 1 行（縦の動画は「縦」の印、収録があれば金色の点）。フォルダーで整理できる: フォルダーはノートに付く名前（`Note.folder`、1 段）で、見出しを押すと開閉（開閉はこの Mac の localStorage に覚える）、ノートを見出しへドラッグすると入り、「フォルダーなし」の領域へドラッグすると出る。「＋ フォルダー」を押すと「新しいフォルダー」がすぐ一覧の先頭にでき、その場で名前を書き換えられる（見出しのダブルクリックでも書き換え）。フォルダーは作った順（新しいものが上）に並び、フォルダーなしのノートはその下（名前の一覧は保存先の `folders.json` に持つ。ノートに付いた名前との和が一覧）。ノート画面の「フォルダー」の選択（新しいフォルダー… で作る）でも入れられる。見出しの「名前」「×」で名前の変更・解散（ノートは消えない）。検索中はフォルダーに関係なく平らに並べる
- プレゼン用の窓: ワークスペースの「プレゼン用の窓」で、黄色い枠だけの別ウィンドウを開く（Zoom や Meet で「この窓」を共有する用）。中身は同じ画面を `#present=<noteId>` で開いたもので、ワークスペース側の MindMap がノートの中身と選んでいるノードを IPC（`present:update` → `present:state`）で 60ms の間隔で流し、プレゼン用の窓の MindMap（mirror）はそれをそのまま映す。開閉・文字・画像・選んだノードに加えて、カメラ（ホイールの拡大縮小、ドラッグの移動、自動ズーム）も 1 フレームごとに `present:camera` で流し、プレゼン用の窓は面の大きさの比で拡大縮小して同じ見え方にする（WYSIWYG）。カメラが届いたあとは、プレゼン用の窓側の自動の全体表示は行わない。窓の比率は 16:9 か 9:16 に固定（setAspectRatio）。プレゼン用の窓では操作できない。閉じるとボタンの表示が戻る
- 縦の動画（ショート）: ワークスペースの下の「横 / 縦」でノートごとに向きを選ぶ（`Note.orientation`）。縦は 9:16 の枠で 1080×1920 の webm に収録し、木は箇条書き型（outline）にする: 根を左上に置き、子は親のすぐ下に 56px 字下げして縦に並べ、開いたノードの下に子が入って後ろの行が下がる。線は親の左端近くから下へ降りて子の左端に入る罫線。幅は階層の字下げ分しか使わないので、縦画面で 1 つ開いても切れない（最初に試した「子が下、兄弟が横」の配置は 1 つ開くと幅を使い切ったのでやめた。コードは direction: down として残してある）。ノードの操作の置き場所は横の木と同じ
- 題名は枠の幅に対する割合で決める（横 3.3% ≒ 1920px で 63px、縦 7% ≒ 1080px で 76px）。長ければ 2 行に折り返す（編集中の入力欄も textarea で同じ見え方。改行は入れない）
- 縦のテロップ: 文字 56px、左右の余白 60px、下からの余白 300px（ショートの画面下のボタン類と重ならないように）、1 つ 16 文字を目安に分ける。ASS の PlayRes は収録の大きさから決める
- ワークスペースの下に「全部閉じる」「全部開く」（子のあるノードをまとめて開閉し、全体を収め直す。⌘Z で戻せる）
- 選んだノードの上の中央に「上に足す」の ＋（Shift+Enter）。操作の並びに「上へ」「下へ」（兄弟の順番の入れ替え。Alt+↑↓ と同じ）と「左へ」「右へ」（階層を上げる = 親の隣に並べる（Shift+Tab）／階層を下げる = 1 つ上のノードの子にする）
- 手で動かした位置にあるノードの下に「下に足す」をすると、新しいノードもその真下（手動の位置）に置く。自動の位置だと、動かしたノードや大きな画像付きノードと重なるため
- 折りたたんだノードの右端の丸には、直下の子の数を出す（孫までは数えない）
- チェックボタン: 四角を押すと「未 ↔ 済」（ワークスペースでも収録中でも。プレゼン用の窓に映るので編集中の付け外しにも意味がある）。ボタンを付ける／外すのは操作の並びのチェック印。Space はボタンがあれば切り替え、無ければ付ける。収録の始めに全部「未」に戻す（終わったあとは戻さない）
- 収録中はノードの中身を変えない（文字の編集・追加・削除・移動・並べ替えは効かない）。できるのは選ぶ・開閉・チェックの付け外しだけ。収録を始めるとき、子のあるノードは全部閉じ（中心も閉じる。話しながら開いていく）、済になっているチェックは全部「未」に戻す（話しながら付けていくため。どちらも ⌘Z で戻せる）。そのあと全体を収め直してから録り始める
- 収録の前に 3・2・1 のカウントダウンを出す（枠の外に重ねるので動画には入らない）。Esc かボタンで取りやめ
- バックアップ: 設定の「バックアップを作る」で、保存先フォルダーを丸ごと選んだ場所へコピーする（`やさしい録音ノート バックアップ YYYY-MM-DD HHMM/`）。特別な形式にはせず、戻すときはそのフォルダーを保存先に指定するだけ
- 一覧側のプレビューは大きさ固定（幅 520px の 16:9）。ウィンドウに合わせて広げない（下の収録一覧が見やすいように）。収録一覧はプレビューの右に並ぶ
- 「音の設定」の「声を整える」（既定オン）: 倍率のあとに DynamicsCompressor（threshold −24 dB、ratio 4、knee 12、attack 5 ms、release 200 ms）を入れる。小さい声を持ち上げ、大きい声は抑えるので、倍率を上げても割れにくい。メーターも同じ道を通す（`src/lib/recording/voice-chain.ts`）
- 書き出しでは声を `loudnorm=I=-16:TP=-1.5:LRA=11` で YouTube 向けの標準の大きさにそろえてから BGM を重ねる（マイクの設定に関係なく十分な大きさになる）
- 「音の設定」の「マイクの音量」（×0.5〜×6）で声の大きさを上げ下げできる。倍率は AudioContext の GainNode でかけ、収録の音声とメーターの両方に同じ倍率がかかる（メーターで見た大きさがそのまま録れる）。収録中に動かしてもすぐ効く。設定に保存する
- 収録の切り出し範囲（黄色い枠）は線も丸角も無しの四角にし、枠の内側だけを切り出す。動画の縁に外の色や線が映らない
- 画面全体やウィンドウの収録（枠以外）は当面作らない。必要になったら追加
- 収録中、マウスの位置とクリックの時刻・位置を記録する（自動ズームの材料）。クリックの検出には macOS の「アクセシビリティ」許可が 1 回必要
- プレビュー、一時停止・再開・停止、経過時間、入力レベル
- 収録中にノートを書ける。収録中に時刻メモを追加でき、あとでその時刻から再生できる

### フェーズ 3: 編集と書き出し

実装済み（2026-09-11）:

- カット編集: 波形（時間軸）をドラッグして消す範囲を選ぶ（黒い取っ手で始まり・終わりを動かせる）。クリックは頭出しだけで再生は始めない。「ここから」「ここまで」（キー I / O、[ / ]）でも決められる。1 コマ（1/30 秒）単位は ← →（Shift で 1 秒）と「−1コマ」「+1コマ」ボタン。Delete で「この範囲を消す」。消した範囲は `media/<id>.json` の `cuts` に持ち、元の webm は変えない。再生では消した範囲を飛ばし、「戻す」でいつでも元に戻る。重なった範囲は 1 つにまとめる（`shared/cuts.ts`）
- mp4 の書き出し: 同梱の ffmpeg（npm の `ffmpeg-static`。配布版では asar の外に置く）で、残す区間を trim / concat でつなぎ、BGM を指定の音量で重ね、H.264（まず Mac のハードウェア `h264_videotoolbox`、だめなら `libx264`）/ AAC 192k / 1920×1080 / 30fps / faststart の mp4 にする。保存先はダイアログで選ぶ（既定はダウンロード）。進み具合をバーで出し、中止できる
- BGM の選択・試し聞き・音量・自動で下げるかは、編集画面の「書き出し」で決める（「音の設定」はマイクとスピーカーだけ）。曲の追加もそこから
- 「話している間の BGM の音量」（既定 30%、元の音量に対する割合）を選べる。声は loudnorm で -16 LUFS にそろえてあるので、sidechaincompress のしきい値 -45 dB・超過 25 dB を前提に、指定の割合まで下がる比率を計算する（0.3 → 10.5 dB 下げ → ratio 1.72）
- BGM は書き出しでループさせ、最初 1 秒でフェードイン、最後 2 秒でフェードアウト。「話している間は BGM を自動で下げる」（既定オン）は sidechaincompress で声を側鎖にして BGM を圧縮する
- 開発時の動作確認は、`YASASHII_USER_DATA`（設定の置き場所）と `YASASHII_EXPORT_DIR`（保存ダイアログを出さずに書く場所）を付けた別インスタンス（`--remote-debugging-port=9223`）で行い、使っている本物のアプリを止めない。本物のアプリの再起動は、収録中でないことを確かめてから行う
- 6 秒の実収録で確認: カット 1.5 秒 → 4.96 秒の mp4（h264 High 1920×1080 30fps、aac 48kHz stereo）。BGM あり／なしの両方で音量差を確認

これから:

- 自動ズーム: 収録中に記録したクリック位置へ、なめらかに寄って、しばらく動きがなければ戻る。寄る倍率、寄る速さ、戻るまでの時間を設定できる
- 手動ズーム: 時間軸に「ここからここまで、この範囲を拡大」を置く。自動ズームの結果を手で直す使い方もできる
- ズームの動きはイージング（ゆっくり始まり、ゆっくり止まる）で補間し、カクつかせない
- プレビューは編集画面上でそのまま再生
- 書き出し: mp4（H.264 / AAC、1080p または元解像度、30fps）。YouTube にそのまま上げられる形式にする
- 書き出しは Canvas で 1 フレームずつ描いて WebCodecs でエンコードし、ffmpeg で mp4 にまとめる。進み具合を表示する

### フェーズ 4: 文字起こし・字幕・要約（API 利用）

実装済み（2026-09-11）:

- テロップ: 編集画面の「テロップを作る」で、収録の声を 16kHz モノラル 48kbps の mp3 にして OpenAI の文字起こし（whisper-1、verbose_json、segment 単位）に送り、文ごとのテロップ（Cue: startMs / endMs / text）にする。時刻は word（単語ごと）の時刻から取る: segment の文を「。！？」で分け、単語を順に当てはめて最初の単語の始まり〜最後の単語の終わりにする。segment の時刻は日本語だと秒単位で始まりが重複するため使わない（word が無いときだけ、前の終わりから始める形で使う）。`transcripts/<recordingId>.json` に保存。API キーは設定に入れ、userData の settings.json にだけ置く（リポジトリには入れない）
- 手でも足せる（「いまの位置に足す」）。文字はその場で直し、「始」「終」でいまの再生位置に時刻を合わせる。消せる。編集画面の動画の上に、いまのテロップを重ねて見える
- 文字起こしのとき、28 文字を超える文は「、」で分けて別のテロップにする（時刻は単語から）。既にあるテロップは「長い文を分ける」ボタンで同じように分けられる（時間は文字数の割合で配る近似）。書き出しのときにも、残っている長いテロップは同じ規則で自動的に分ける（手で書いた長い文も対象。押す操作は要らない）。区切りが無い長い節は、できるだけ均等な長さに切る
- 書き出しの前に、直したテロップを必ず保存してから ffmpeg に渡す（入力直後の未保存分が反映されない事故を防ぐ）。入力欄を離れたときも保存する
- 書き出し: 「テロップを動画に焼き込む」（ASS を作り ffmpeg の subtitles フィルター。フォントは Mac のヒラギノ丸ゴ ProN、白い帯（92% 不透明、BorderStyle 3）の上に墨色の太字、下から 64px、1920×1080 基準。長い文は 1 行の上限（文字サイズから計算。60px なら 28 字）を超える手前の句読点で折り、2 行に入らなければ 48px（3 行まで）、それでも入らなければ 40px にして枠の外で切れないようにする）と「.srt も一緒に保存」（mp4 と同じ名前）。時刻はカットを外したあとの時刻に直し、消した範囲のテロップは落とす（`shared/cues.ts`）
- 25MB（1 時間ほど）を超える音声はまだ送れない（分割は今後）

- 収録から音声を抽出し、文字起こし API に送る。単語ごとの時刻を受け取る
- 字幕は文（発話のまとまり）ごとに出す。話し始めた瞬間に文がまとめて表示され、1 語ずつ流す形式にはしない
- 字幕の文の区切りと表示時刻は、あとから編集画面で直せる
- 字幕（SRT / VTT）を生成。書き出し時に動画へ焼き込むか、別ファイルとして保存するかを選べる。YouTube には mp4 と srt を別々に上げるのが基本
- 文字起こしをノートに貼り付け、要約・見出し案・箇条書きを AI で作る
- API キーは設定画面で入力し、キーチェーンに保存する
- YouTube への直接アップロード（YouTube Data API）は任意。設定の手間があるため、まずは「mp4 と srt をファイルで出す」まで

## 5. 画面収録の制約（正直に書く）

- **相手の声**: 取らない（用途は自分の声だけの収録）。将来必要になった場合は macOS の ScreenCaptureKit が必要で、別途検討する。
- **表示は事実どおり**: 取れていない音声を取れているように見せない。
- **クリック検出**: 自動ズームのためのクリック検出は macOS の「アクセシビリティ」許可が要る。許可がない場合は、マウス位置だけを使ったズームにとどめ、その旨を表示する。
- **確認は実機で**: 合成ストリームで動いた項目と、実際のマイク・画面・共有音声で確認した項目を分けて報告する。実機で確認できていない項目は「確認済み」にしない。

## 6. 画面と部品の構成

ノートは「左に一覧、クリックした瞬間に右へ全体像が出る」2 画面構成にする。一覧側では編集しない。
編集と収録は「ワークスペース」（画面全体）で行う。ノートの中身はマインドマップで、タイトルのノードを左に置き、右端の丸いボタンで子ノードが右へ開く（タイトルも同じ仕組み）。

## 9. 決定事項（2026-09-11 回答）

1. 収録は自分の声だけ。相手の声は不要。用途は YouTube に上げる自分の画面収録。
2. クリック位置へ自動で寄る自動ズームは必要。動きはなめらかに。
3. 字幕は文単位で、話し始めに表示。時刻の調整はあとから編集できるようにする。YouTube は mp4 と srt を出すところから。
4. 形態はデスクトップアプリ（Electron + SvelteKit）で進める。
- 送信中の目印: SNS へのアップロード・予約の登録（`publish:hubPost` / `publish:youtubeUpload`）の間、main は userData/busy.json を書く（1 分ごとに更新、終わったら消す）。`scripts/dev/deploy-app.sh` はこの目印が 15 分以内なら入れ替えを中止する（送信の途中でアプリを開き直さないため）。
- 投稿済みの判定（`isPosted`）にハブの仕事の様子を渡すと、取り消し・失敗した予約の記録は「投稿済み」に数えない。投稿管理の「残り」と SNS投稿 の判子に効く。
- 投稿できる時間帯は 12:00〜23:30（2026-09-15 に 6:00 始まりから変更。ハブの cron も UTC 3〜14 時）。投稿管理の格子は 12〜23 時、1 時間の見出しの下に :00 と :30 の 2 枡（30 分きざみで置ける）。格子は枠いっぱいに広がる。
- サムネの欄は SNS投稿 の左（`publish/ThumbnailCard.svelte`、動画のすぐ下）に独立した。左の並びは 動画 → ステータス → 投稿先 → サムネ → 投稿日（2026-09-16。投稿日は投稿管理で決めるので最後。ステータスの説明文は外した）。YouTube を使わなくても「投稿文を確定する」で図つきサムネを写して `drafts.youtube.thumbnailPath` に入れる（投稿管理の札に出すため）。YouTube の欄からはサムネの節を外し、投稿の直前に `onCapture` で写す
- 大きい動画のアップロード（2026-09-15）: Cloudflare は 1 回の HTTP 本体が 100 MB までなので、`electron/lib/publish/upload.ts` は 64 MB 超を 48 MB ずつの multipart（`POST /api/media/multipart` → `PUT …/:key/:uploadId/:n` → `POST …/complete`、失敗したら `DELETE` で捨てる）で上げる。ハブ側は R2 の createMultipartUpload / resumeMultipartUpload。全体は 2 GB まで。実機の 120 MB（3 片）で中身の一致を確認済み
- 先頭から何秒送るか（`postOne`）: 動画の長さが分からない古い書き出しでも draft.trimSec があれば切る。投稿先の上限（X 140 秒・Threads 300 秒・Instagram 90 秒）を超えるなら指定が無くても上限で切る。`recordings:exportInfo` は長さが無ければ ffmpeg で測って書き出しの記録に覚える
- 投稿の記録を足すときは `withPostRecords`（shared/types.ts）を通し、その投稿先に手で付けた投稿済み／未投稿の印を消す（印が残ると送ったのに「残り」に出続けた）
- 投稿管理: 「確定する」でできなかったものは、閉じるまで赤枠のカードに出しておく（通知だけだと消えて分からない）
- 投稿管理の「確定する」は `src/lib/stores/schedule.svelte.ts`（置いた変更 pendings・送信中の説明 applying・進み具合 ratio・できなかったもの lastErrors）で動く。画面を閉じても送信は続き、閉じている間は画面の隅の帯（ExportBar、緑）に出る。置いた札も画面を閉じて戻っても残る。送信中に ⌘Q すると main が「送信を待つ／終了する」を聞く（busy.ts の hasRunningPublishes）
- 書き出し履歴の 1 本は必ず 1 行: 丸・日付・（長さ・大きさ、または予約してあれば赤い縁の「予約済み」の札。斜めにしない）・小さい SNS投稿・削除。右の列は 300px ほどしかないので、札と長さ・大きさは同じ場所を使い分ける（全文はホバー）
- TikTok（2026-09-15、ハブ側だけ実装。接続は TikTok の開発者ポータルの設定待ち）: `hub/src/platforms/tiktok.ts`。Login Kit（OAuth 2.0 + PKCE、scope `user.info.basic,video.publish`、redirect `/connect/tiktok/callback`）→ Content Posting API の Direct Post（creator_info を聞いてから `video/init`、FILE_UPLOAD で 10 MB ずつ Content-Range 付きで PUT、`status/fetch` で PUBLISH_COMPLETE 待ち）。審査前（Sandbox・未監査）は公開範囲 SELF_ONLY のみ。審査後は wrangler.toml の vars に `TIKTOK_AUDITED = "1"`（それまでは選択に関わらず SELF_ONLY 固定）。鍵は `wrangler secret put TIKTOK_CLIENT_KEY / TIKTOK_CLIENT_SECRET`。横の動画は Instagram と同じく帯付きの縦にしてから上げる。ユーザー名は creator_info の creator_username
- ハブの副要求（subrequest）の上限（2026-09-15 の事故）: Cloudflare の無料プランは 1 回の呼び出しで 50 件まで。cron が X・Threads・Instagram・Facebook を 1 回の呼び出しで順に進め、Facebook の処理待ちの途中で "Too many subrequests" になった。直し: (1) `STEPS_PER_CALL`（12 歩）を超えたら Yield して進みを保存、(2) cron（runDue）は仕事を 1 件ずつ、自分への service binding `SELF`（`POST /api/jobs/:id/step`）経由の新しい呼び出しで進める（呼び出しごとに上限が新しくなる）、(3) `failJob` はやり直しのときも state を残す（消すと Facebook の動画が二重になる。実際に 1 本重複した）。Facebook の /videos 一覧は処理が終わるまで新しい動画を出さないので、「まだ無い」と早合点しない
- TikTok の投稿の設定（2026-09-15、審査の決まり）: ハブ `GET /api/tiktok/creator`（creator_info: 表示名・選べる公開範囲・コメント/デュエット/ステッチの可否・長さの上限）を、SNS投稿の TikTok の欄が投稿の前に読んで出す。投稿者が「公開範囲（選べるものだけ）」「許可する（コメント・デュエット・ステッチ。TikTok 側で止めてあるものは選べない）」「宣伝の申告（宣伝を含む → 自分のブランド / ブランドコンテンツ）」を選び、`PostDraft.tiktok`（`TikTokPostOptions`）に保存、`HubPostRequest.tiktok` でハブへ。ハブは post_info の privacy_level / disable_* / brand_organic_toggle / brand_content_toggle に反映。ブランドコンテンツ × 自分のみは不可（`tiktokOptionsError`）。同意文（音楽利用の確認、ブランドコンテンツポリシー）を欄の下に出す
- 既定の投稿先（2026-09-15）: YouTube・X・Threads・Instagram・Facebook の 5 つ。TikTok（審査が通るまで自分のみ）と note は既定でオフ（`defaultTargets`）。保存済みの下書きはそのまま
- note（2026-09-15）: 公式の投稿 API が無いので手で貼る。`Platform` に 'note' を足し（HubPlatform からは除く）、`publish/NotePublish.svelte` が題・Markdown の本文（AI が作る: `composePrompt` の note の規則。短い段落・## 見出し・箇条書き・800〜1500 字）・結び（`noteClosing`: 「この話は YouTube でもお話ししています」+ その書き出しの YouTube の URL、無ければチャンネル URL）を出し、「コピーして note を開く」でクリップボードに入れて https://note.com/notes/new をブラウザーで開き、note の投稿の記録（PostRecord）を足す。投稿管理の「残り」と日程の対象からは外す。`postOne('note')` は投げる
- note の記事は別の呼び出し（`composeNote`、gpt-4.1、書き起こしを時刻なしで全部、Markdown をそのまま返させる。JSON にすると短くなる）。長さの目安は `noteTargetChars`（書き起こしの 9 割、2,000〜8,000 字）で「要約ではなく話したことを全部文章に」と指示。題は常に動画の題（欄では編集しない。AI の題で上書きせず、先頭の題らしい 1 行は外す）
- note への貼り付けは HTML でコピーする（`src/lib/publish/note-html.ts` の小さな Markdown → HTML: #/##/### 見出し・段落・- と 1. の箇条書き・**太字**・---・URL）。note の編集画面は Markdown の記号を文字のまま貼るので、text/html と text/plain（Markdown）の両方をクリップボードへ（ClipboardItem）。だめなら plain だけ
- note のハッシュタグ: 記事の生成で最後に「タグ: a、b、c」の行を作らせ（5〜8 個）、`composeNote` が切り出して `ComposeResult.note.tags` → `draft.tagsText`。欄では , 区切りで直せ、札を押すと 1 語ずつコピー（note のハッシュタグ欄は 1 語ずつ入れる）、「全部コピー」で `#a #b` の形。本文には入れない
- 投稿する範囲（2026-09-16）: ハブ経由の欄は「始まり」と「終わり」を別々に選べる（`PostDraft.startSec`（null = 先頭）と `trimSec`（先頭からの位置。null = 最後まで））。終わりは始まり + 上限（X 140 秒など）まで、始まりは終わりの 5 秒前まで。動かすと互いに直す（setStart / setEnd）。「▶ 始まりを確かめる」は始まりから 5 秒、「▶ 終わりを確かめる」は終わりの 5 秒前から（`previewRange(from, to, …, kind)`）。時間の帯は範囲だけ濃く。`HubPostRequest.startSec` → `prepareVideo` が `-ss start -i … -t (end-start)`、途中からなら音を 0.5 秒で上げる。`PostRecord.fromSec` に記録（「45 秒から 50 秒まで」と出す）。手元のハブで 20〜30 秒を送って 10.00 秒の mp4 になるのを確認
- 投稿する部分の帯（2026-09-16、スライダーをやめた）: 1 本の帯の濃いところ（投稿する範囲）をつかんで動かす（長さはそのまま）、両端のつまみで伸び縮み。動かしている間は左の動画がその秒で止まって映り（`onScrub` → `scrubTo`）、放すと始まり（または終わり）の 5 秒を流す。帯の下に範囲の両端の時刻、濃いところの中に長さ。数字の入力は無し。「全部にする／先頭から上限まで」の札だけ
- SNS の本文の規則（2026-09-16）: 箇条書きは「話の要点の数だけ（2〜5 個）」で 3 個固定にしない。X・Threads は 1 個 15 文字以内、Instagram は 12 文字以内（ぱっと読める）、Facebook は 20 文字以内。Threads は 200 文字以内。YouTube の hashtags を AI が省いたら tags から作る（逆も）。temperature 0.5
- 投稿管理は今日の 2 日前から 14 日（`PAST_DAYS`）。過去の日と今日の過ぎた枡には置けない（斜線）。過去の日には「もう出したもの」（ハブの仕事が done、または YouTube・note の記録）を薄い札で出す（動かせない・× 無し・押すと SNS投稿へ）
- 投稿管理の札は 116px 固定でサムネを 16:9 のまま全部見せる（枡より広く、隣にかぶってよい）。載せると手前に来るだけ（拡大しない）。出したものは透けさせず縁をグレーに
- 投稿管理の札は「同じ書き出し・同じ時刻（分）」の予約をひとまとまりにする（X・Threads・Instagram・Facebook が 1 枚。`groupItems`）。動かすと全部の仕事を同じ時刻に、× は全部取り消す（YouTube は Studio で）。出したものは予約した時刻（scheduledAt）の枡に出す（実際に上がった時刻が遅れても、予定どおりの位置）。「+N」は枡の右上に重ねて札の幅を取らない
- テロップの作り話（2026-09-16）: whisper は静かな所や終わりで prompt（辞書・ノートの言葉）をそのまま吐くことがある（「やさしいバイブコーディング」「やさしい図解レコーダー」が末尾に出た）。`dropHallucinations` が verbose_json の no_speech_prob / avg_logprob / compression_ratio を見て、prompt の中の言葉と同じで確信の低い segment・無音の確からしさが 0.85 超・繰り返し 2.4 超を落とす（console に記録）。`cleanTranscriptText` は未定義・私用・制御のコード（U+FF00 が □ で出た）を落とす
- 辞書の言葉の作り話（追加）: 最後の segment の末尾に辞書（設定の transcriptTerms）の言葉が連なっていれば、その前までを残す（`termsTail`。「経営者、やさしいバイブコーディング、やさしい図解レコーダー。」→「経営者」）。辞書の言葉だけを並べた segment は落とす。文の中に混ざる本当の発言（「やさしい図解レコーダーの話をします」）は残る。raw.segments に no_speech_prob / avg_logprob / compression_ratio も残す
- whisper の prompt は文の形（`buildPrompt`: 「この動画では、A、B などについて話します。X、Y という言葉も出てきます。」）。言葉を「、」で並べただけだと、whisper がその書き方をまねて動詞や語尾を落とし名詞の羅列にした（「配達員、経営者、」）。同じ音声で比べて、文の形なら「配達員奪われます、経営者残ります」と話したとおりになった
- テロップは 2 つのモデル（2026-09-16）: 文は `gpt-4o-transcribe`（話した動詞・語尾を落とさない。時刻は返さない）、時刻は `whisper-1` の word。並行して呼び、文を「。！？」と長さで分けて、whisper の単語列にあいまいに当てる（`locateFuzzy`: 半大域の並べ合わせ、4 割以上が順に一致すれば同じ文。後ろへは戻らない。見つからなければ文字数の半分だけ進める）。gpt-4o-transcribe がだめなら whisper の文で。費用は 1 分 0.012 ドル（whisper だけの 2 倍。30 分で 40 円弱）。始まりが同じになった短い文は 0.3 秒ずらして消えないように
- テロップは whisper-1 だけ・prompt 無しに戻した（2026-09-16、上の 2 つの試みは取り下げ）。ヒント（辞書・ノートの言葉）を prompt に入れると書き方をまねて動詞を落としたりヒントを吐いたりし、2 モデル（gpt-4o-transcribe + whisper）は費用 2 倍のうえ本物の環境で位置合わせが崩れた。固有名詞の書き方は「置き換え」（書き起こし後に機械的に当てる）と「誤りの候補を出す（AI）」（辞書とノートの文脈を渡す）で直す。残すのは無音の作り話（no_speech_prob > 0.85）と繰り返し（compression_ratio > 2.4）の除外、□ になるコードの除去、後ろへ戻らない位置合わせ（あいまいな探索は whisper 自身の segment と word のずれにだけ使う）
- テロップの文字の欄で日本語入力が二重に入った（2026-09-17、「どっか」→「どっかどっか」）: 変換中（isComposing）の input では状態に入れず、確定（compositionend）で入れる。変換を確定する Enter / 取り消す Esc では欄から出ない（変換中に欄を離れると、変換中の文字が確定と一緒に二重に入る）。いまのテロップの欄と一覧の欄の両方
- テロップが全部前にずれた（2026-09-17、35 分の収録）: no_speech_prob は 30 秒の窓ごとに同じ値が付くので、本当に話している 26 秒分の segment 5 つが 0.851 で丸ごと落ち、その word（130 文字）が探す範囲（先 40 文字）を超えてしまい、あとの文は近くの似た並びにあいまいに当たって遅れが積み上がった（終わりで 12 分ずれ）。直し: (1) 無音の作り話は whisper 本体と同じ「no_speech_prob > 0.6 かつ avg_logprob < -1.0」だけ落とす。(2) `toCues` は文ごとに元の segment の始まりを持ち、新しい segment に入るたびに探し始めをその始まりの 1 秒前まで進める（word の始まりは segment の始まりと同じ時刻なので安全。間の segment が落ちても、そこから先は自分の segment の中で当たる）
- YouTube の予約の取り消し（2026-09-17）: 投稿管理の予約の札の × で、ハブの仕事と同じように YouTube も取り消せる。予約公開は動画そのものなので、`publish:youtubeDelete`（videos.delete）で上げた動画を消し、収録の posts からその記録を外す（「残り」に戻る。もう一度予約するときは上げ直す）。削除には youtube.force-ssl の許可が要るので SCOPE に足した。接続時に Google が返す scope を `youtubeAuth.scope` に覚え、無ければ設定の YouTube の所に「つなぎ直してください」と出す（`youtubeCanDelete`）。古い接続のまま取り消すと 403 で、つなぎ直しを促す
- 送っている途中の取りやめ（2026-09-17）: 投稿管理で「確定する」のあと、送っている札の × を押すと `schedule.cancelPending(id)`。まだ送っていない変更は外すだけ、送っている途中なら `publish:cancel`（`electron/lib/publish/cancel.ts`）でいまのアップロードを次の区切り（YouTube は 8MB の塊、ハブは 48MB の片・段階の境）で止め、その変更の残りの投稿先も送らない。上げ終わる前の YouTube は動画が作られない。もう上げ終わった投稿先はそのまま予約される（通知で伝える。取り消しはハブの札の × / YouTube Studio）。送っている間に置いた別の変更は消さない（以前は × で一覧から消えるだけで送信は続き、確定の終わりに pendings を全部消していた）
